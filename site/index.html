Prison letters: a small demo

Twenty letters from the American Prison Writing Archive, used to ask three questions about AI tools that run on local computers. Full essays are not shown here; the archive remains the place to read them.

Introduction: what "local models" means

Everything on this page that involved AI was done by local models: AI models whose files were downloaded once onto an ordinary desktop computer (a Mac) and run there, the way you would install and run any other program. The letters, the page scans and the results never left that computer.

That is different from uploading a document to Claude, ChatGPT or Gemini. When you upload, a copy of the letter goes to the company's servers and is processed there, under that company's terms for storage, retention and review. Even with "don't train on my data" settings, the archive no longer holds the only copy, and cannot fully control or recall it. For a collection whose authors keep their copyright, can ask for their work to be taken down, and may face real consequences from what they wrote, that matters.

What local gives an archive: the text stays in-house; it can work with no internet connection; there is no per-page fee; and the exact model version is fixed, so results can be checked and reproduced later.

What it costs: local models are smaller than the largest cloud models, they need a capable computer, and someone has to set them up. Part of what this demo asks is whether they are good enough anyway.

Honesty note: the code for this demo was written with help from Claude, an AI coding assistant, which looked at a few excerpts and page crops while checking the work. The transcription, entity extraction and theme tagging of the letters themselves all ran on the local models below.

Which models, and why

JobModelWhy this one
Transcribe the scans olmOCR 2 (7 billion parameters, Allen Institute for AI) Built specifically for reading document images, and small enough for a desktop. Earlier tests on historical documents picked it as the model to build on.
Qwen3-VL 8B Instruct (Alibaba's Qwen team) A general-purpose vision model of similar size, to compare a specialist with a generalist. Run in two programs (Ollama and oMLX) to see whether the software running the model changes the result.
Qwen3-VL 32B Instruct The same family at four times the size, to test whether a bigger model reads handwriting better. It did not: the small models were as accurate.
The PDF's own text layer Not an AI model: the text already embedded in the archive's PDFs, as a baseline.
Find places, prisons, laws, programs; tag themes Gemma 4 26B (Google, open weights) Good at following instructions and returning structured results. Every item it finds must be an exact quotation from the letter, checked by code, so it cannot invent entities.
Search by meaning bge-small-en-v1.5 (Beijing Academy of AI) Small enough to run inside your web browser, so your search words are not sent anywhere either.
Locate snippets on the scans Apple Vision (built into macOS) and Tesseract Conventional text recognition used only to find where text sits on the page, so the right crop can be shown and names, ID numbers and addresses blacked out.

All the models are "open-weight": anyone can download and run them. None of them was trained on or adapted to this archive. Transcription was scored against the archive's own human transcriptions, which are treated as the correct answer.
